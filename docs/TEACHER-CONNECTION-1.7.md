# LearnFlow学习流动 1.7.0：课程协作与模型连接

本版补充教师课程流程、策略使用说明，以及可以查看实际回应的模型连接验证。网页与连接助手一起更新；旧版 PPT、解决方案 PDF 和 Buddy 组件包本轮未重制。

## 可以做什么

| 入口 | 已实现的操作 | 当前范围 |
| --- | --- | --- |
| 教师课程 | 建课程、生成邀请链接或邀请 JSON、导入学生学习包 | 数据分别保存在各自浏览器，没有共享后台或认证账号 |
| 学生提交 | 逐条选择对话，预览内容与 Token 来源，确认后生成学习包 | 默认零选中；导出和交给教师均由本人决定 |
| 教师反馈 | 用授权模型生成教学策略评价草稿，人工核验后形成反馈 | AI 草稿不是已核验结论或正式成绩 |
| 针对性作业 | 根据选定证据生成作业草稿，教师修改、确认发布；学生提交，教师验收 | 跨设备用 JSON 学习包交换，不是在线同步课堂 |
| 策略说明 | 8 张默认策略的原始指令、方法步骤、适用情况、限制及四轮对话示例 | 示例为明确标注的编写示例，不冒充真实用户记录；默认策略可复制后编辑 |
| QQ | 确认后发送单次提醒、读取学习收件箱、人工关联证据 | 不按 QQ 收件或提醒送达自动判断作业完成 |
| 模型连接 | 选择本机 WorkBuddy 或 LearnBuddy，授权后做实际回应验证 | 安装客户端、读取模型列表、验证成功是不同状态 |

聊天、图片与文件上传、学习资料保存、个人记忆确认和策略导出继续保留。

## 教师和学生怎样使用

1. 教师建立课程，检查课程信息，再复制邀请链接或导出邀请 JSON。
2. 学生导入课程，自己决定提交哪些学习对话。提交界面默认不选任何记录；先检查内容及真实、估算、未知用量，再确认生成学习包。
3. 教师导入学习包，查看原始证据。需要 AI 协助时，明确选择材料并调用已授权模型；评价结果先保存为草稿，由教师核验。
4. 教师可继续生成针对性作业草稿，编辑后确认发布。学生完成后提交，教师根据产出验收。
5. 不同电脑之间导入、导出 JSON 学习包。邀请链接用于携带课程信息，不等于建立账号、远程班级数据库或实时协作权限。

QQ 提醒需要本人确认发送范围、对象和内容。收件箱里的消息可以由人关联到学习证据；收到一句“完成了”不能代替教师验收。

## 怎样确认模型真的可用

1. 在“连接与模型”中选择本机找到的 WorkBuddy 或 LearnBuddy。线上网页首次使用须安装连接助手，并在本机窗口确认网页授权。
2. 读取模型列表只表示客户端声明了这些模型。选择模型不会自动调用它，也不会立即显示验证通过。
3. 点击同意验证后，网页发送一道简短算式和本次随机生成的 `LF-xxxxxxxx` 校验码。回答须包含正确结果 `133` 和对应校验码，才显示验证成功。
4. 验证面板显示请求与返回内容、客户端、实际返回模型、耗时和用量。验证失败、取消、模型切换后，状态按本次结果更新；不把旧模型的成功沿用到新模型。

验证后端有 55 秒上限；关闭验证会取消对应请求。聊天中可停止生成，已收到的正文和未发送草稿会保留。没有回应时可以选择 Auto 再试，不自动连续重试消耗额度。

教师草稿可以取消；关掉所属窗口、离开课堂或开始人工修改时，会停止对应生成。晚到的回复不能覆盖人工编辑。教师请求使用单独的简短草稿提示，不携带学生聊天中的记忆和引子；支持时使用客户端的低思考强度。等待上限为本机请求 120 秒、网页兜底 125 秒。

本机本轮发现的是 **WorkBuddy 和 LearnBuddy 内置的 CodeBuddy CLI**；未发现独立安装在 PATH 中的 CodeBuddy 客户端。这条路线通过客户端调用云端模型服务，不是运行本地模型权重，也不等于已接入 LearnBuddy 官方 Open API。

## 已取得的真实连接证据

| 本机客户端 | 选择 | 实际返回模型 | 本次耗时 | 结果 |
| --- | --- | --- | --- | --- |
| WorkBuddy | Auto | deepseek-v4-flash | 8.506 秒 | 返回 `133` 与本次随机校验码 |
| LearnBuddy | Auto | deepseek-v4-flash | 7.657 秒 | 返回 `133` 与本次随机校验码 |

记录见 [WorkBuddy 浏览器验证](../output/model-verification/workbuddy-browser-proof.json) 与 [LearnBuddy 浏览器验证](../output/model-verification/learnbuddy-browser-proof.json)。这些耗时是各一次实际测量，不是服务速度承诺。

`hy4-preview` 在本次基线尝试中等待 35 秒未返回正文，随后人工中止，因此本次未验证通过。这个结果不足以判断它永久不可用，也未确定该次等待的服务端原因。

真实学习与教学流程也已验证：

- LearnBuddy Auto 实际解释条件概率并出题，返回模型为 `deepseek-v4-flash`，服务报告输入与输出合计 6,532 Token；该回答及调用记录已显示在聊天页。
- 由测试者从零勾选开始选择两条片段，确认后提交到课程空间；教师看到的内容与学生选择一致，6,532 Token 随学习包保留。
- WorkBuddy Auto 生成了真实评价草稿，返回 `minimax-m3`，耗时 34.031 秒。评价指出学生尚未提交独立解答；表单仍为“待核验”，没有自动确认成绩。
- WorkBuddy Auto 生成针对性的三小题作业草稿，返回 `deepseek-v4-flash`，耗时 23.790 秒，服务报告 5,438 Token；“确认布置”仍未勾选。

这些测试使用测试者编写的提问和示例课程，不是真实学生教学实验。Auto 的实际模型会变化。第一次 LearnBuddy 教师评价请求在 120 秒内未返回正文；随后精简教师请求上下文并改用 WorkBuddy 完成上述验证，不能据此断言超时根因已经由服务端查明。真实回答、评价、作业和回执保存在 `output/model-verification/real-*`。

## Token 怎样显示

- 真实用量优先采用服务返回的总数；没有总数时，使用返回的输入量与输出量相加。
- 缓存读取和缓存写入量在接口回执中分列保存，不再叠加到总数。
- 预设演示估算与真实接口用量分开；服务未返回的用量标为未知。
- 用量用于检查调用情况，不是账单，也不等于学习效果。课程提交前，学生能看到这一区别。
