# 学习流答辩逐页讲稿

共16页。建议主讲约8分钟，现场演示约2分钟；按实际赛事时限删减。不要读页脚；保留对能力状态的准确说明。

## 演示顺序

1. 打开本地学习工作台，确认预设演示标签。
2. 进入应试或自主学习，开启词根词缀或六级证据策略。
3. 完成一段示范交互，提出并确认候选记忆。
4. 查看生成的专属策略，再演示关闭、导出与恢复。
5. 打开教师评价草稿，说明学生选择分享、教师人工核验。

## 第 01 页｜学习流

各位评委好，我们是来自中国地质大学（北京）的学生团队。我们想解决一个很具体的问题：AI 已经能讲很多知识，但自主学习者仍然需要决定今天做什么、采用什么方法，以及怎样知道自己真的学会了。学习流把学习方法做成可选择的策略卡片，并让经过本人确认的经验成为下一次学习的起点。本次带来的是本地可运行工作台、策略组件和 Buddy 应用配置材料，尚未完成平台审核和用户效果实证。

## 第 02 页｜AI 会回答，学习还需要下一步。

我们不预设所有用户都缺学习方法，也不认为现有平台没有记忆。我们要验证的，是三个具体成本：选方法的成本、从答案变成行动的成本，以及把已经磨合好的方法复用的成本。第一轮访谈会要求受访者复现最近一次中断的学习过程，再观察他们使用原型的实际行为。首批聚焦我们能够直接触达的大学生，避免在没有资源和证据时同时覆盖全部学段。

## 第 03 页｜把学习方法变成一条可执行的流程。

学习流的核心是一条闭环，而不是更多角色。先确认目标和可投入时间，再选择适合的策略，完成一个有明确产出的学习块。学完后用复述、练习或项目产出检验，系统只能提出候选记忆，必须由本人确认才形成专属策略。下次可以复用，也可以停用。这样，学习方法和用户选择都能在界面上看见，出现问题时也能定位到底是哪一步出了问题。

## 第 04 页｜打开就知道从哪里开始。

这一页展示本次实际运行的网页。用户可以从三类场景起步，检索和开启卡片，完成示范学习流程并确认记忆。本地数据能够保存和导出。我们明确区分三种状态：可运行交互已经完成；对话默认是预设演示；真实 Buddy 能力还需应用身份、用户授权和联调。这不是多人在线社区，页面上也不会把预置数据说成真实用户行为。现场可以按下一页的例子完成整个操作链。

## 第 05 页｜一张策略卡，不止一种说话口吻。

策略卡片不是给模型起一个专家名字。每张卡都需要输入、明确的步骤、输出和完成标准，并说明失败时怎样调整。例如检索练习，必须先要求用户回忆，再提供答案和反馈；如果模型先把答案展示出来，即使语气很像老师，也没有忠实执行这个机制。卡片还需要版本、来源和许可，便于用户迁移以及团队维护。我们保留评分和使用量，但不会用消耗了多少 token 来证明学得更好。

## 第 06 页｜今天磨合一次，下次少说很多。

以单词学习为例，用户用词根词缀策略完成一段练习。系统提出一个候选：你是否希望先拆词根，再给短例句，并用表格展示？用户可以修改、确认、跳过，或把适用范围限制为英语空间。确认后才形成专属策略。我们把这种表达偏好与实际掌握程度分开，后者需要新句子辨认、回忆或迁移题证据。鼓励强度和语言风格也由用户设置，系统不会借记忆来隐藏施压。

## 第 07 页｜同一套内核，三种学习入口。

应试入口用六级 Skill 作为原生样例，重点是答案隔离、定位证据、干扰项和错因，而不是把推断包装为命题内幕。自主学习入口解决资料来源和知识路径，读不懂时先回溯前置知识。项目入口帮助学生从选题走向里程碑、分工和可验证成果。三个入口共享状态、策略和证据结构，所以团队可以先把一个场景做稳，再扩展。高难科研代做和未经核验的研究结论不属于当前产品主轴。

## 第 08 页｜让教师看到过程，让学生保有控制。

我们对教师侧的定位是辅助教学设计与过程性评价。教师可以提供目标和量规，学生完成策略执行后预览并选择提交证据包，包含产出、关键练习表现和修订记录。AI 组织草稿并引用证据，教师最终核验。默认不把原始对话、私人记忆和社交记录交给教师。命题中的管理在第一阶段聚焦学习任务、版本和授权协作，不把当前原型说成完整教务系统。

## 第 09 页｜方法可以保留，底座可以替换。

架构有四层：最上面是工作台，下面是稳定的学习数据和事件协议，再下面是策略执行与工具，最后是平台适配。Agent Skills 已有开放格式，承载工作流程；MCP 用来连接外部工具和资源，不能简单说 Skill 必须进化为 MCP。我们减少平台依赖的方法，是明确输入输出和权限，保留结构化证据，并用同一组样例检查模型变化。真正可积累的是策略与评测，前端只是可见入口。

## 第 10 页｜已经准备应用材料，逐关完成平台接入。

我们核验了腾讯官方开放平台：Buddy 应用需要控制台配置、客户端预览和审核。开发者入驻文档列有个人和企业两类认证，所以现在既不能断言必须注册公司，也不能保证个人有全部发布权限。真实 Open API 需要已审核应用和 OAuth 用户授权。当前交付十个策略、四个专家候选包、只读 MCP、配置源稿和字段映射，本地协议验证不等于宿主认证，不伪称已经发布。下一步先核验实际后台权限，再决定采用个人、学校支持或企业合作主体。

## 第 11 页｜已有强底座，我们争取做出可验证的增量。

LearnBuddy 已公开提供专家、长期学习记忆和生态连接，ChatGPT 学习模式也有引导提问、理解检验和记忆。因此我们的差异化不能建立在贬低现有产品上。我们希望证明的是：用户看得见当前策略，能把经验带走，能检查策略执行，并能将证据交给教师。如果平台未来原生加入这些功能，团队仍可以提供高质量策略、评测样例与校园实施反馈，这也是项目能够进退的原因。

## 第 12 页｜先证明流程可用，再检验学习效果。

验证分三层。第一层检查机制是否真的执行，比如检索题是否先泄露答案、记忆是否经过确认。第二层用八到十二人的主持式测试观察能否独立完成任务。第三层计划约三十人的短期试用，比较同等材料和同模型基础流程，记录基线和七天延迟测验，尽可能盲评分，并报告退出原因。这个规模主要用于发现问题和估计差异，不能直接宣称普遍提分。评分、token 和安装量都不代替效果证据。

## 第 13 页｜十名学生，从一个学习场景跑通。

我们有十名大二学生，建议四人负责产品与学习研究，四人负责开发与质量，两人负责开源、试点和答辩，并让每个成员保留能够解释的独立贡献。十二周先设置五千元现金支出上限，这只是内部预算分配，不是平台报价。推广从一个具体任务开始，通过 GitHub 提供可运行材料和问题反馈，再逐步做社区内容。未来可能的持续方式是课程配置、评测和实施服务，当前没有客户或收入需要宣称。

## 第 14 页｜12 周，把不确定性逐个变成证据。

第一阶段确认需求并把最小闭环做稳，第二阶段在取得权限后联调真实能力并开展试用，第三阶段依据失败案例修订、开源发布和准备送审。每个阶段都有退出条件，没达到就缩小范围。对外展示有 GitHub Pages 与 Netlify Drop 两条静态路线，现场保留本地版本。公开前端不会自动获得模型权限，也不会自动成为多人服务。我们的目标是现场能演、素材能审、平台状态能说明。

## 第 15 页｜把校园里的真实学习过程，变成可复用能力。

面向腾讯，我们希望交付的是三类可以直接审阅的成果：可复用的学习策略和课程模板；来自校园的工作台交互、失败案例与改进记录；以及检验策略执行的评测集和经过授权的试点证据。我们需要的合作也很具体：确认发布主体和权限、提供官方接口联调支持、帮助找到真实校园试点，并明确品牌使用边界。我们不会把尚未发生的对接描述为联合研发。

## 第 16 页｜学习方法可以分享， 学习的决定权属于你。

我们希望学习流最终留下的，不只是一次 AI 回答，而是用户能够理解、选择、修改并带走的学习方法。本次交付已经把这种想法做成可以操作的本地工作台和可审阅的策略组件。下一阶段会通过真实使用、授权接入和延迟测验检验它的价值，并如实公开失败与局限。学习方法可以在社区流动，但是否记忆、怎样学习以及分享什么，应始终由学习者决定。谢谢各位评委。

## 临场边界用语

- “已实现”只用于实际可运行交互与组件。
- “预设演示”用于未连接真实模型的对话。
- “待授权联调”用于需要应用身份和用户授权的官方能力。
- “应用配置材料”不改称“已发布 Buddy 应用”。
- 样本数、预算、收入或提分均须说明实际状态；当前没有用户实证结果。
