# LearnFlow学习流动 · Buddy 应用开发路线图

这份路线图把答辩材料里的产品愿景，拆成 Buddy 平台真正能配置、工程现在能开发、平台审核后才能验证的三层。项目名称统一为 **LearnFlow学习流动**，应用头像使用团队提供的 F 形标识；不使用 LearnBuddy 官方头像、猫咪标识或“官方应用”表述。

## 先定边界

Buddy 应用的核心价值是“行业 Harness”：WorkBuddy 提供宿主、模型、工具编排和权限，LearnFlow 配置学习场景、学习方法、提示词、专家、连接器和面板。能发挥的重点是入口和流程设计，而不是修改宿主首页、侧栏、模型菜单或客户端 DOM。

答辩 PPT 已经确定三类场景：应试复盘、自主学习、项目式学习；核心差异是可解释的学习策略卡片、用户确认后的个人策略、学习资产和教师过程性评价。PPT 中仍属计划的跨设备同步、QQ 主动提醒、真实课堂试点和社区规模，必须在 Buddy 版本中按“待授权/待试点”表达。

## 线路 A：现在就能完成的 Buddy 工程（本地 MVP）

1. **服务骨架**：Node.js 24 服务提供标准 Streamable HTTP MCP、`ui://learnflow/workspace.html` MCP Apps 面板和健康检查。模型由宿主提供，服务只处理学习数据和权限。
2. **学习入口**：配置三个工作模式——复盘错题、学点新的、把项目做出来；配置七个场景胶囊，引导用户从一个具体任务开始。
3. **策略卡片**：内置 11 张策略，全部包含做法、步骤、示例、适用情况、限制和证据口径。用户能查看、启停、编辑个人版本，未选择的方法不自动生效。
4. **记忆与资产**：模型只能创建学习块或个人策略草稿；面板提供编辑、取消、版本校验和本人确认。PDF 仅复制用户亲自选择的文件，保存后可以再次读取、预览或下载。
5. **教师课程**：教师建课并生成邀请码；学生加入后选择提交对话片段；AI 只写评价和作业草稿；教师人工核验、发布，学生提交后教师确认。
6. **策略流动**：个人策略默认私有，用户主动发布后才出现在共享列表；可以采纳、撤回和提交自报反馈。反馈和 Token 自报不冒充平台计量，也不作为学习成绩。
7. **权限和持久化**：SQLite 记录账号隔离、草稿版本、课程状态、资料元数据和授权撤销。面板专用操作与模型工具分开，保存/发布不能由模型参数代替。

本线路的本地入口是 `buddy-app/service`。运行 `npm ci` 后执行 `npm run preview`，打开 `http://127.0.0.1:4318/preview`。三个身份按钮只用于隔离演示，不读取真实 Buddy 登录信息。

## 线路 B：接入官方 Buddy 控制台

在控制台按五个模块填入源稿：

| 控制台模块 | LearnFlow 配置 | 当前状态 |
|---|---|---|
| 创建应用 | 名称、F 形头像、简介、最小身份权限、回调和可信 Origin | 等平台生成 App ID/Client ID 并审核 |
| 首页配置 | Slogan、三个模式、七个场景胶囊、远程 MCP 入口 | 文案与资源已准备，平台资源 ID 待回填 |
| 市场配置 | 11 个 Skill、4 个专家候选、远程连接器和精选场景 | 本地 slug 不能冒充平台资源 ID |
| 其他配置 | 中英文占位符、绑定说明、模型组合和默认排序 | 必须以当时真实模型池为准 |
| 预览调试 | 指定客户端预览、面板回传、模型调用和错误恢复 | 企业身份与客户端预览完成后验收 |

配置源稿为 `buddy-app/app.config.source.json`，它是人工填表材料，不是官方导入格式。官方平台没有为本工程生成的 App ID、Client Secret、Skill ID 或模型 ID，不能自行编造。

## 线路 C：公开服务与生态分发

1. 选择支持 Node.js 24、HTTPS 和持久磁盘的部署环境；静态 GitHub Pages/Netlify 只托管展示页，不能代替 MCP 后端。
2. 设置 `LF_PUBLIC_URL`、`LF_DATA_DIR`、`LF_WORKBUDDY_CLIENT_ID`、`LF_WORKBUDDY_CLIENT_SECRET` 和精确的 Origin 白名单。密钥只放部署环境，不进 GitHub、Skill、PPT 或 ZIP。
3. 用标准 MCP OAuth 完成发现、动态注册、S256 PKCE、一次性授权码、刷新轮换和撤销。上游 WorkBuddy 凭证只用于身份识别，不转发给客户端。
4. 先以单实例小规模试用；备份完整数据目录。扩成多实例前更换共享数据库和文件存储，不能依赖各实例自己的本地盘。
5. 远程连接器经腾讯审核后再加入 Buddy 内置能力。QQ、微信、腾讯会议等逐项验收“生成、发送、送达、用户确认、教师核验”状态，不把文案生成说成已送达。

## 验收门槛

本地工程验收：服务测试、授权测试、浏览器面板测试全部通过；确认后的资产重启后仍可读；跨账号不能读取；旧版本不会被悄悄替换。真实模型测试要同时看到工具调用和草稿落库，只有模型返回文字或用量不算接通。

官方发布验收：主体审核通过、应用创建审核通过、资源 ID 回填、公开 HTTPS 可访问、OAuth 绑定/撤销通过、指定 Buddy 客户端能显示 MCP Apps 面板、至少两个模型完成策略读取与草稿流程、连接器和配置审核通过。任一项未完成时，交付包应明确写“待平台验证”。

## 当前可交付物

- `buddy-app/service/`：持久化服务、MCP Apps 面板和部署模板。
- `buddy-app/app.config.source.json`、`modes/`、`skills/`、`experts.source.json`：控制台填表和能力源稿。
- `buddy-app/connector/remote/`：远程 OAuth MCP 连接器候选材料。
- `docs/BUDDY-CONSOLE-GUIDE.md`：控制台回填、授权、部署和发布闸门。
- `scripts/test-buddy-store.mjs`、`scripts/test-buddy-service.mjs`、`scripts/test-buddy-oauth.mjs`、`scripts/test-buddy-panel.mjs`：本地存储、HTTP/MCP、授权和真实浏览器验收。
- `output/buddy-service-0.3/`、`output/buddy-panel-0.3.0/`：脱敏检查报告和截图。

下一步顺序固定为：先运行本地 MVP → 申请/完成应用主体与创建审核 → 回填官方资源 ID → 部署 HTTPS 服务 → 用指定客户端预览 → 逐项补做模型和连接器验收 → 提交配置审核 → 小范围试用并依据反馈迭代。
