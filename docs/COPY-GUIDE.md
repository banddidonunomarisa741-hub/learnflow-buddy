# LearnFlow学习流动：文案约定

用户来这里是为了学东西，不是听产品介绍。按钮先说动作，回答先回应问题。趣味可以来自学生熟悉的处境，但不要在出错、授权或删除资料时开玩笑。

|场合|采用的表达方向|
|---|---|
|还没开始|问他今天想弄懂什么，给少量可选起点。|
|正在等待|显示真实进度，允许停止。不要一直留着空白。|
|答错或卡住|指出具体卡点，提供下一步。不要自动夸“你已经很棒了”。|
|讲解|先解释本轮问题，必要时给例子。专业词确实有用才保留。|
|建议|提出可以直接做的动作，允许改写和忽略。不要每轮喊口号。|
|保存|说明保存什么、保存在哪里、能否改或删。|
|连接失败|说明发生了什么，以及可执行的处理办法。|

删掉没有信息量的升华、整齐排比、假装深刻的反转以及过度亲昵。正式方案保留必要术语、证据与限制，不为“活泼”损害准确性。不要编造经历、成果或价格来制造真实感。

本次按用户要求检索并审阅 GitHub 原项目：[blader/humanizer](https://github.com/blader/humanizer) 与 [syw2039/humanizer-zh](https://github.com/syw2039/humanizer-zh)。两者采用 MIT 许可；它们用于检查表达，本项目的产品文案另行编写。审阅日期：2026-09-06。本地研究副本位于 output/research-current，不作为额外运行依赖。

这份约定不承诺绕过 AI 检测，也不把写作特点当作作者身份的证据。后续团队人工文案优先于这份临时约定。
